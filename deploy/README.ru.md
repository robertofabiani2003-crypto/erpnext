# Файлы работающего деплоя

Снимок разрешённых файлов `/opt/erpnext` на 11.11.2026. Исходники ERPNext находятся
в корне этого репозитория, инфраструктура Frappe Docker закреплена подмодулем
`vendor/frappe_docker` на commit `adb65c3e6bea083095bb88dc45f589ab37ead072`.

На сервере `/opt/erpnext/source` — checkout этой же рабочей ветки GitHub.
Работающий сайт использует ранее собранный образ, а не bind mount checkout.
`Containerfile` проверяет точные commit ERPNext и Frappe; `apps.json` фиксирует
релиз ERPNext. Изменения документации не требуют пересборки образа.

После клонирования получить подмодуль командой `git submodule update --init`.
Рабочие копии этих файлов находятся непосредственно в `/opt/erpnext`; скрипт
`build.sh` рассчитан на этот каталог и на соседний `frappe_docker`.
Подмодуль позволяет получить тот же build context на другом компьютере.
В снимок включены Compose, Containerfile, список приложений, скрипт сборки,
digest базовых образов и проверочные Python-скрипты. Скрипты проверки не выводят
пароли; `verify-background.py` создаёт короткое задание в выбранной очереди.

Секреты `/opt/erpnext/secrets.json`, `/opt/erpnext/db-password`, конфигурация сайта,
база, файлы пользователей, резервные копии и журналы остаются на сервере вне Git.
Не копировать их в checkout. `compose.yaml` читает пароль из внешнего файла.
Файл пароля необходим для проверки `docker compose config` и запуска на новом
хосте, но в репозитории его нет.

Перед обновлением кода работающего сайта: проверить чистоту checkout, получить
нужный commit без принудительного reset, создать резервную копию, собрать образ,
проверить миграции и только затем обновлять сервисы. Обычный `git pull` меняет
исходники и сам по себе не развёртывает новую версию сайта.

## Автоматический деплой

Основная ветка GitHub и production: `develop` (стабильная ERPNext v16). Изменения делаются в отдельных
ветках и сливаются PR в `develop`. Локальная папка подключена через origin;
незакоммиченные изменения сами в GitHub не отправляются.

На сервере systemd `erpnext-auto-deploy.timer` проверяет GitHub каждые 60 секунд.
`/opt/erpnext/source` обновляется только fast-forward и только при чистом дереве.
Новый образ содержит точный Git commit ERPNext поверх закреплённого рабочего
образа Frappe. Смена зависимостей требует ручного обновления базового образа.
После сборки: maintenance, остановка очередей, backup базы и файлов, migrate,
перезапуск приложения и проверка `/api/method/ping`. База и пользовательские файлы
остаются в существующих volumes. Конфигурация `/opt/erpnext/compose.yaml` и секреты
остаются вне checkout; изменение deploy/compose.yaml требует ручного применения.

Статус: `systemctl status erpnext-auto-deploy.timer` и
`journalctl -u erpnext-auto-deploy -n 100`. Установленный commit:
`cat /opt/erpnext/deployed-revision`. При ошибке после начала обслуживания
автоматические попытки того же commit блокируются файлом `failed-revision`.
После устранения причины удалить этот файл и запустить сервис повторно.
При ошибке миграции нельзя автоматически откатывать только образ: требуется
проверка базы и при необходимости восстановление backup. Предыдущий образ
сохранён в `/opt/erpnext/previous-image.yaml`.

Отключить: `systemctl disable --now erpnext-auto-deploy.timer`.
Сборка и миграции занимают время; на этапе миграции сайт временно недоступен.

Русификация: штатный ERPNext-словарь находится в erpnext/locale/ru.po,
словарь Frappe — в базовом образе. Дополнительные 18 переводов хранятся
в базе сайта. Скрипт deploy/localization/apply_glossary.py воспроизводит их
без перезаписи конфликтующих переводов. Он не запускается автоматически.
Проверка deploy/localization/verify_demo.py читает настройки и тестовые документы.
Настройки языка, валюты и часового пояса сохраняются в базе, а не в Git.
